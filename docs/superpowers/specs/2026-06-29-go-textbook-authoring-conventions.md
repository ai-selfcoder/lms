# Конвенции авторинга учебника по Go (ПП-2 и ПП-3)

Общий контракт для всех агентов, пишущих главы. Цель — связный, человеческий,
понятный джуну учебник с интерактивными примерами, исполняемыми **в браузере**.

## Тон и язык

- Русский. Дружелюбно к джуну, без снисходительности и без «воды».
- Объясняем «почему», а не только «как». Сначала интуиция/аналогия, потом точность.
- Короткие абзацы, активный залог. Термин вводим один раз и по-русски + англ. в скобках
  при первом упоминании (напр. «срез (slice)»).
- **Свой текст.** Ориентир по фактам — Tour of Go / ardanlabs/gotour, но формулировки,
  структура и примеры — оригинальные. Не копировать.

## Формат файла

- Глава — `content/<course>/book/<slug>.mdx`.
- Frontmatter строго:
  ```yaml
  ---
  title: "Человеческое название"
  slug: "<slug>"
  order: <число>
  minutes: <оценка чтения>
  ---
  ```
- Заголовки внутри — `##` и `###` (без `#`: H1 рисует страница из `title`).

## Структура главы

1. Вводный раздел «О чём глава» — зачем это джуну, 1–2 абзаца.
2. Понятия по порядку: короткая проза → пример. Нарастающая сложность.
3. **Интерактивные примеры** через ` ```go play ` (см. ниже) — джун меняет и запускает.
4. «Частые ошибки» — 2–4 типичных грабли с краткими объяснениями.
5. «Что дальше» — мостик к следующей главе и кросс-ссылки.

## Интерактивные примеры (`go play`) и лимиты движка

Примеры исполняются интерпретатором **yaegi → WASM прямо в браузере**. Учитывать:

- Запускаемый блок — ` ```go play ` (с метой `play`). Обычный ` ```go ` — статичный,
  для не-исполняемого кода/псевдокода/фрагментов.
- Полная программа: `package main` + `func main()`. yaegi сам вызывает `main()`.
- **Доступный stdlib** (курированный): `fmt errors strings strconv sort math
  math/rand time sync sync/atomic context bufio bytes unicode unicode/utf8`.
  Пакеты `os`, сеть, генеричные `slices`/`maps` — **недоступны** в playground.
- Горутины/каналы/`select` — работают (под wasm однопоточно). Завершать горутины
  через `sync.WaitGroup` или приём из канала, чтобы вывод успел напечататься.
- НЕ полагаться на настоящий параллелизм или race-детектор — их в браузере нет.
  Если пример про гонку/параллелизм «вживую» — давать **статичным** ` ```go ` с
  разбором, без кнопки запуска, и честно это проговаривать.
- Каждый `go play` должен давать детерминированный, осмысленный вывод через `fmt`.
- Держать примеры короткими (обычно ≤ ~25 строк) — это playground, не проект.

## Кросс-ссылки

- На соседние главы того же курса: `/go-basics/book/<slug>` или `/go/book/<slug>`.
- Из основ — мостик в продвинутый курс по конкурентности, где уместно.
- Внутренние ссылки — обычным markdown `[текст](/путь)`.

## Чего не делать

- Не копировать чужой текст. Не выдумывать несуществующие API/пакеты.
- Не использовать в `go play` недоступные пакеты (см. список) — пример не запустится.
- Не плодить H1, не менять схему frontmatter, не трогать чужие главы.
