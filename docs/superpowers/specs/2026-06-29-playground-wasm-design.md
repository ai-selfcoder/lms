# ПП-1: Интерактивный playground (yaegi → WASM) — дизайн

Дата: 2026-06-29
Часть roadmap: `2026-06-29-go-textbook-roadmap.md` (под-проект 1).
Статус: согласован дизайн, ожидает ревью спека.

## Цель

Дать читателю учебника запускаемый блок кода: меняешь Go-код прямо на странице,
жмёшь «Запустить» — видишь вывод. **Исполнение полностью в браузере, нулевая
нагрузка на сервер.** Компонент переиспользуется обоими учебниками (ПП-2, ПП-3).

## Жёсткое ограничение

Только клиент. Никаких сетевых вызовов для запуска кода. Движок —
**yaegi** (`github.com/traefik/yaegi`, чистый Go-интерпретатор) скомпилированный
в `GOOS=js GOARCH=wasm`. Существующий серверный грейдер учебник не использует.

## Архитектура

```
Книжная страница (SSR, renderMarkdown → HTML-строка, как сейчас)
        │  rehype-плагин помечает ```go play блоки
        ▼
<div data-runnable data-code="…"> + статически подсвеченный код внутри (fallback)
        │  клиентский <RunnableMounter> сканирует [data-runnable], гидрирует острова
        ▼
<Runnable> (React, "use client")
   ├─ показывает статичный код, пока не нужен интерактив
   ├─ Monaco (lazy: грузится по фокусу/клику «Запустить»)
   ├─ кнопки ▶ Запустить / ⟲ Сбросить
   └─ вывод → DS <Terminal>
        │  через singleton-клиент → postMessage({id, code})
        ▼
ОДИН общий Web Worker на страницу (PlaygroundWorker)
   ├─ грузит wasm_exec.js + play.wasm лениво при первом запуске
   ├─ инстанцирует yaegi-интерпретатор со stdout/stderr → буфер
   └─ отвечает {id, stdout, stderr, err, durationMs}
        ▲
   Watchdog (главный поток): таймаут 5с → worker.terminate() →
   «⏱ превышен лимит времени (5с)» → респаун воркера к следующему запуску
```

### Почему так

- **Островная гидрация.** Текущий рендер — markdown → доверенная HTML-строка
  (намеренно без MDX/JSX-парсинга, чтобы Go-синтаксис в прозе не ломал парсер,
  см. `lib/markdown.ts`). Мы не меняем эту модель: добавляем rehype-плагин,
  который превращает `go play`-фенсы в плейсхолдер-остров, и клиентский маунтер,
  гидрирующий их через `createRoot`. Статичный подсвеченный код виден сразу
  (SSR), интерактив — прогрессивное улучшение.
- **Один воркер на страницу.** WASM качается и инстанцируется один раз, даже
  если на странице 10 примеров. Запуски сериализуются (очередь по `id`).
- **Web Worker + `terminate()`** — единственный надёжный способ убить
  бесконечный цикл (`for {}`), не вешая вкладку. На главном потоке прервать
  синхронный wasm-вызов нельзя.

## Компоненты и интерфейсы

| Юнит | Файл (предполож.) | Назначение | Зависит от |
|---|---|---|---|
| `cmd playwasm` | `site/playwasm/main.go` (+ свой `go.mod`) | обёртка yaegi: принимает код из JS, исполняет, возвращает результат | yaegi, syscall/js |
| build-скрипт | `site/playwasm/build.sh` + npm `build:playwasm` | сборка `GOOS=js GOARCH=wasm` → `web/public/play/play.wasm` + копия `wasm_exec.js` | Go toolchain |
| worker | `web/lib/playground/worker.ts` | загрузка wasm, протокол run, перехват вывода | play.wasm |
| клиент-синглтон | `web/lib/playground/client.ts` | один воркер/страница, очередь, watchdog/таймаут, респаун | worker |
| `<Runnable>` | `web/components/play/Runnable.tsx` | редактор + кнопки + вывод | Monaco, `@/ds` Terminal/Button, client.ts |
| `<RunnableMounter>` | `web/components/play/RunnableMounter.tsx` | сканирует `[data-runnable]`, гидрирует | Runnable |
| rehype-плагин | `web/lib/markdown.ts` (доп. `.use(rehypeRunnable)`) | `go play`-фенс → плейсхолдер-остров | — |

### Протокол воркера

```
main → worker: { type: "run", id, code }
worker → main: { type: "loading" }                       // первый раз, во время загрузки wasm
worker → main: { type: "ready" }
worker → main: { type: "result", id, stdout, stderr, err, durationMs }
```

Watchdog живёт в `client.ts`: на каждый `run` ставит `setTimeout(5000)`. Если
`result` не пришёл — `worker.terminate()`, отдать вызвавшему «timeout», создать
новый воркер (следующий запуск снова лениво загрузит wasm).

### Фенс-синтаксис в контенте

````
```go play
package main
import "fmt"
func main() { fmt.Println("привет") }
```
````
Обычный ```go (без `play`) остаётся статичным — как сейчас. Опциональный мета-флаг
`norun` зарезервирован, если понадобится «редактируемый, но без запуска».

## Обработка ошибок и состояния

- **Загрузка среды:** при первом запуске — «Загрузка среды Go… (один раз)».
- **Ошибка компиляции/интерпретации:** текст ошибки yaegi в `<Terminal>` со
  статусом `compile`/`fail`.
- **Таймаут:** «⏱ превышен лимит времени (5с)», статус `timeout`.
- **Падение воркера/wasm:** грейсфул-сообщение, воркер респаунится; кнопка
  «Запустить» снова активна.
- **Нет WebAssembly/Worker (древний браузер):** остров не гидрируется, остаётся
  статичный код (прогрессивная деградация).

## Честные риски yaegi и митигации

| Риск | Реальность | Митигация |
|---|---|---|
| Размер `.wasm` | yaegi + полный stdlib symbol table тяжёлый | Курируем подмножество stdlib (fmt, strings, strconv, errors, sort, slices, maps, math, math/rand, time, sync, context, bufio, unicode). Замер в спайке. |
| Generics | в yaegi частичные/с багами | В ПП-2 почти не нужны; в ПП-3 помечаем главы, где не запускаем |
| Горутины | под wasm/js однопоточно (GOMAXPROCS=1), нет race-детектора | Каналы/select/горутины — runnable (учат корректно); настоящий параллелизм/гонки — статичный разбор с оговоркой |
| Краши интерпретатора | редко на экзотике | грейсфул-ошибка + респаун воркера |

## Объём MVP (YAGNI)

**В scope:** `cmd playwasm` + build-скрипт; общий воркер с таймаутом/terminate;
`<Runnable>` с ленивым Monaco и выводом через `Terminal`; rehype-плагин
`go play` + `<RunnableMounter>`; курированный stdlib; состояния загрузки/ошибки/
таймаута; **1 живой пример в существующей главе как доказательство**.

**Вне scope (потом):** серверный fallback (запрещён ограничением), мультифайл,
stdin, шаринг/сохранение сниппетов, автосейв, сам контент учебников (ПП-2/ПП-3).

## Порядок реализации

1. **Спайк (gate):** минимальный `play.wasm`, замерить размер (gzip) и прогнать
   5 сниппетов, включая горутину с каналом и `time.Sleep`. Критерий прохода:
   размер приемлем для ленивой загрузки (ориентир ≤ ~6–8 МБ gzip) и сниппеты
   дают корректный вывод. Если нет — стоп, возвращаемся к развилке движка.
2. Воркер + протокол + watchdog (`worker.ts`, `client.ts`).
3. `<Runnable>` + ленивый Monaco + `Terminal`.
4. rehype-плагин `go play` + `<RunnableMounter>`, подключить в book-рендер.
5. Живой пример в главе, проверка в preview (вывод, таймаут на `for {}`,
   несколько блоков на одной странице → один воркер).

## Тестирование / проверка

- Спайк-сниппеты дают ожидаемый вывод (ручная сверка).
- `for {}` → срабатывает watchdog, вкладка не виснет, следующий запуск работает.
- Несколько `go play` на странице → один воркер (проверка в Network: один
  запрос за `play.wasm`).
- Деградация: при отключённом JS/Worker виден статичный код.
- Mobile/preview: первая загрузка не блокирует рендер страницы.

## Открытые вопросы (решаются в спайке/плане)

- Где хранить `play.wasm`: коммитить артефакт или собирать в CI.

  полную программу. (Предпочтение: разрешить и полную программу, и «голый» body —
