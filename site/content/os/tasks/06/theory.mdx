## Идея first-fit

Аллокатор хранит список свободных блоков. На запрос размера `r` он идёт по списку
слева направо и берёт **первый** блок, в который `r` помещается — отсюда название
*first-fit*. Это быстро и просто, но со временем оставляет «дырки»
(фрагментацию).

В этой задаче мы убираем самую сложную часть — **освобождение**. Если память
никогда не возвращается, свободная область всегда остаётся одним сплошным куском
справа. Значит, весь «список свободных блоков» сводится к одному числу — границе
между занятой и свободной памятью.

```text
 занято            свободно
[========|--------------------]
 0     cursor                size
```

## Как считать

1. Заведи `cursor = 0` — смещение начала свободного хвоста.
2. Для каждого запроса `r`:
   - если `r <= size - cursor` — кусок влезает: запиши в ответ `cursor`, затем
     `cursor += r`;
   - иначе запиши `-1` и **оставь `cursor` как был**.
3. Длина ответа = длина `requests`.

## Грабли

- **Не двигай курсор при отказе.** Иначе сломаешь случай, когда крупный запрос не
  влез, а следующий мелкий должен поместиться в остаток.
- **Граница включительна.** Запрос ровно по размеру остатка (`r == size - cursor`)
  должен влезать — используй `<=`, а не `<`.
- **Пустой вход.** Для `requests == nil` верни пустой срез, а не `nil`-панику:
  цикл просто не выполнится.
- **Нулевой/отрицательный размер запроса** в этой задаче не рассматривается —
  считаем `r >= 1`.
