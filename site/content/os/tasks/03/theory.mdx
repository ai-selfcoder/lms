## Идея base-and-bounds

Процесс думает, что его память начинается с адреса 0 и тянется непрерывно. На
деле ОС положила его куда-то в физическую память. Чтобы примирить эти две
картины, железо при каждом обращении к памяти делает две вещи:

- **перемещение (relocation):** прибавляет `base` — физический адрес начала
  процесса;
- **проверку границы (bounds check):** убеждается, что виртуальный адрес меньше
  `bound` — размера выделенной области.

```text
виртуальное            физическое
адресное пространство  пространство
0      ┌──────────┐    base   ┌──────────┐
       │   код    │           │   ...    │
       │  данные  │  +base →  │   код    │  ← сюда лёг процесс
bound  └──────────┘           │  данные  │
                       base+bound └──────────┘
```

Это ровно тот механизм, что разбирается в главе
[«Трансляция адресов»](/os/book/address-translation) — здесь ты собираешь его
проверку руками.

## Как считать

1. Проверь нижнюю границу: `va >= 0`. Отрицательный виртуальный адрес
   невозможен.
2. Проверь верхнюю границу: `va < bound`. Валидны индексы `0 .. bound-1`.
3. Обе проверки прошли — верни `(base + va, true)`.
4. Хотя бы одна не прошла — верни `(0, false)`.

## Грабли

- **`va == bound` — это уже мимо.** Если `bound == 16384`, то последний
  допустимый адрес — `16383`. Граница задаёт размер, а не последний индекс.
  Используй строгое `<`, а не `<=`.
- **Не забудь про нижнюю границу.** Отрицательный `va` тоже выход за пределы,
  хотя `base + va` мог бы дать «красивое» число.
- **При провале адрес именно 0**, а не `base + va`. Второе значение `false`
  само по себе сигнал об ошибке, но контракт фиксирует и первое — возвращай
  ноль.
