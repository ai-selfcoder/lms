## Идея

inode — это «паспорт» файла: метаданные плюс ссылки на блоки с данными. Прямых
указателей мало (их место в inode ограничено), поэтому для больших файлов вводят
**косвенные** указатели: ссылку на целый блок, заполненный другими указателями.
Каждый новый уровень косвенности умножает доступную ёмкость на `p` —
число указателей в одном блоке.

Эта механика подробно разобрана в главе
[«Реализация файловой системы»](/os/book/fs-implementation).

## Как считать

1. Найди, сколько указателей влезает в один блок: `p = blockSize / ptrSize`.
2. Посчитай вклад каждого вида указателей **в блоках данных**:
   - прямые → `direct`;
   - single-indirect → `p`;
   - double-indirect → `p*p`;
   - triple-indirect → `p*p*p`.
3. Сложи всё — получишь общее число блоков данных.
4. Умножь на `blockSize` — получишь размер в байтах.

```text
        inode
   ┌───────────────┐
   │ direct[0..N-1] │ ─────────────► данные            (direct блоков)
   │ single  ──────┐│
   │ double   ─────┐│
   │ triple    ───┐││
   └──────────────┼┼┼┘
                  │││
   single ───►[ p указателей ]───► данные              (p блоков)

   double ───►[ p указателей ]──►[ p указателей ]──► данные   (p*p блоков)

   triple ───►[ p ]──►[ p ]──►[ p ]──► данные          (p*p*p блоков)
```

## Грабли

- **Косвенные блоки не считаются как данные.** Блок указателей хранит адреса, а не
  байты файла — поэтому в ёмкость идут только конечные блоки данных (`p`, `p*p`,
  `p*p*p`), но не промежуточные блоки указателей.
- **Не забудь про `direct = 0`.** Косвенные указатели работают независимо от числа
  прямых; при нулевых прямых файл всё ещё может быть огромным.
- **Защита от деления на ноль.** Если `blockSize` или `ptrSize` не положительны,
  считать `p` нельзя — верни `0`.
- **Числа большие.** На 64-битной платформе `int` спокойно вмещает результат
  (для 4 КБ блоков это триллионы байт), но помни: на 32-битной `int` переполнится.
