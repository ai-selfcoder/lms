## Идея

Виртуальный адрес — это не одно число, а **пара**: номер страницы и смещение внутри неё. Размер страницы — степень двойки, поэтому адрес естественно делится на два поля по границе бит. Старшие биты — номер виртуальной страницы (VPN), младшие — смещение (offset).

```text
pageSize = 16 = 2^4  -> младшие 4 бита это offset

   va = 35 = 0b100011
              \__/\__/
               VPN  offset
              = 2    = 3
```

Таблица страниц — это просто массив: по индексу VPN лежит номер физического кадра. Трансляция меняет **номер страницы** на **номер кадра**, а смещение переносит без изменений — внутри страницы расположение байтов одинаково в виртуальном и физическом пространстве.

```text
виртуальный:  [ VPN=2 ][ offset=3 ]
                  |  table[2] = 5
                  v
физический:   [ frame=5 ][ offset=3 ]  = 5*16 + 3 = 83
```

## Как подступиться

1. Раздели адрес: `vpn = va / pageSize`, `offset = va % pageSize`. Для степени двойки это эквивалент сдвига и маски, но деление/остаток читаются проще и работают так же.
2. Проверь, что `vpn` попадает в таблицу: `0 <= vpn < len(table)`. Иначе — page fault `(0, false)`.
3. Проверь валидность записи: если `table[vpn] < 0` — тоже page fault.
4. Собери физический адрес: `table[vpn]*pageSize + offset`, верни `(pa, true)`.

## Грабли

- **Смещение не масштабируют.** Частая ошибка — умножить на `pageSize` весь адрес или прибавить `offset*pageSize`. Кадр умножается на `pageSize`, а `offset` прибавляется как есть.
- **Кадр 0 принимают за «пусто».** Валидность определяется условием `< 0`, а не `== 0`. Кадр с номером 0 — это абсолютно нормальная страница в начале физической памяти.
- **Забывают проверку границ таблицы.** Обращение `table[vpn]` без проверки `vpn < len(table)` уронит программу паникой при `vpn` за пределами — это как раз тот page fault, который надо обработать аккуратно.
- **Пустая таблица.** При `len(table) == 0` любой `vpn >= 0` сразу выходит за границы — должно вернуться `(0, false)`, без паники.
