## Зачем это на собесе

Любой сервис обязан уметь корректно останавливаться: по сигналу (SIGTERM от
Kubernetes) дать фоновым задачам дослать буферы, закрыть соединения, дописать
файлы — но не ждать вечно, а отвести на это конечный **grace-период**, после
которого завершить принудительно. Интервьюер проверяет связку
[context](/book/context) для отмены + `WaitGroup` для ожидания + `select` против
таймаута, и понимание, что зависшую задачу нельзя ждать бесконечно.

## Что нужно знать

Отмена раздаётся через **общий `ctx`**, который все задачи получают одинаковым.
Когда внешний код вызывает `cancel()`, закрывается `ctx.Done()` — это broadcast,
его видят все задачи разом (древовидная отмена из [context](/book/context)).

Ожидание завершения — `sync.WaitGroup`: каждая задача в горутине с `defer
wg.Done()`. Но `wg.Wait()` блокирует, а нам нужно «ждать, но не дольше grace».
Приём — превратить `Wait` в канал:

```go
done := make(chan struct{})
go func() { wg.Wait(); close(done) }()

select {
case <-done:
    // все завершились
case <-time.After(grace):
    // не уложились — принудительно
}
```

Это та же идиома, что в fan-in (задача 09): отдельная горутина закрывает `done`
после `Wait`, и `select` выбирает «все доделали» против «истёк grace». Подробнее —
[select](/book/select), [sync](/book/sync-primitives).

## Идиомы и паттерны

- **Общий `ctx` для всех задач** — древовидная отмена: один `cancel` будит всех.
- **`WaitGroup` → `done`-канал.** Превращаем блокирующий `Wait` в селектируемое
  событие, чтобы наложить таймаут.
- **`select` «done vs time.After(grace)»** — гонка между «успели» и «не успели».
- **Возврат `nil`/`error` как контракт shutdown** — `nil` при graceful, ошибка при
  принудительном завершении.

## Подводные камни

- **`wg.Wait()` напрямую без таймаута.** Если хоть одна задача игнорирует `ctx` и
  висит, `Wait` заблокируется навсегда — сервис не остановится. Именно поэтому
  `Wait` оборачивают в `select` против `time.After(grace)`.

  ```go
  // как НЕ надо: зависнет на застрявшей задаче
  <-ctx.Done()
  wg.Wait()
  return nil
  ```

- **Захват переменной цикла.** В `for _, task := range tasks` до Go 1.22 нужно
  передавать `task` параметром в горутину — иначе все горутины запустят последнюю
  задачу. Эталон это и делает (`go func(t ...){ ... }(task)`).

- **Старт горутин после `<-ctx.Done()`.** Задачи надо запустить **до** ожидания
  отмены, иначе они даже не начнут работать. Сначала запуск, потом `<-ctx.Done()`.

- **«Утечка» застрявшей горутины.** При принудительном завершении зависшая задача
  остаётся жить — это осознанный компромис: мы не можем убить горутину извне в Go.
  Важно лишь, чтобы `RunService` **вернулась**, не дожидаясь её (об утечках —
  [утечки и гонки](/book/leaks-and-races)).

- **`grace` отсчитывается не от старта, а от отмены.** Таймер `time.After(grace)`
  должен запускаться **после** `<-ctx.Done()`, иначе grace «сгорит» ещё до сигнала.

## Как подступиться

1. Запусти каждую задачу в горутине с общим `ctx`: `wg.Add(1)`, внутри
   `defer wg.Done(); t(ctx)`. Передавай `task` параметром.
2. Заблокируйся на `<-ctx.Done()` — ждём сигнал на остановку.
3. После сигнала: `done := make(chan struct{})`, горутина `wg.Wait(); close(done)`.
4. `select`: `<-done` → `return nil`; `<-time.After(grace)` → верни ошибку
   принудительного завершения.

Дальше — решай сам. Эталон открывай после.
