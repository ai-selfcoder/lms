## Race не исправляется повторным чтением

**Симптом.** Счётчик иногда меньше ожидаемого, а `go test -race` показывает конфликт чтения и записи.

**Причина.** Атомарность отдельной операции не делает составную последовательность (прочитать → изменить → записать) безопасной. Два worker-а могут потерять обновление между этими шагами.

**Trade-off.** Mutex проще для инвариантов из нескольких полей; atomic подходит для одного счётчика при использовании `Add`/`Load` без промежуточного обычного доступа.
