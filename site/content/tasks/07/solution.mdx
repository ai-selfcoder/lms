## Идея решения

`sync.Once` гарантирует однократный запуск `init` и блокирует всех вызывающих до
её завершения. Результат (`error`) сохраняется в поле и возвращается каждому,
включая тех, кто `init` не выполнял.

## Разбор эталона по шагам

Структура хранит `Once`, функцию инициализации и её результат:

```go
type Initializer struct {
	once sync.Once
	init func() error
	err  error
}

func NewInitializer(init func() error) *Initializer {
	return &Initializer{init: init}
}
```

`once` — нулевое значение `sync.Once` уже готово к работе, инициализировать его
не нужно. `err` хранит результат первого (и единственного) запуска.

Вся логика — в `Do`:

```go
func (i *Initializer) Do() error {
	i.once.Do(func() {
		i.err = i.init()
	})
	return i.err
}
```

`once.Do` берёт на себя три вещи сразу:

1. **Однократность.** Даже если 200 горутин вошли в `Do` одновременно, `init`
   выполнит только одна. `TestInitializerRunsOnce` проверяет `calls == 1`.
2. **Барьер ожидания.** Остальные 199 горутин *блокируются* внутри `once.Do`,
   пока первая не завершит `init`. Поэтому никто не вернётся с пустой/недописанной
   `err` — `init` спит 20ms, и все честно ждут.
3. **Видимость памяти.** `Once.Do` устанавливает happens-before между записью
   `i.err = ...` внутри `f` и чтением `return i.err` после `Do`. Запись `err`
   гарантированно видна всем — отдельная синхронизация не нужна.

`return i.err` отдаёт результат всем вызывающим, в том числе тем, кто только
дождался чужого `init`. Повторный `Do()` уже не запускает `init` (она была), но
возвращает ту же сохранённую `err` — это проверяет `TestInitializerPropagatesError`.

## Почему именно так

- **`init` ровно один раз.** Оба теста ассертят `calls == 1`, включая случай
  повторного `Do()` после завершения.
- **Ошибка доходит до всех.** `sentinel`-ошибка из `init` приходит каждому из
  200 вызывающих и при повторном `Do()` — потому что лежит в поле `err`.
- **Нет гонок.** Запись `err` — только внутри `Do`; чтение — после возврата из
  `Do`. happens-before от `Once` закрывает гонку, `-race` чист.

## Альтернативы и их минусы

- **Ручной флаг `done bool`.** `if !i.done { i.err = init(); i.done = true }` —
  гонка: при одновременном входе `init` выполнится несколько раз, флаг читается
  без синхронизации. Падает на `-race` и на `calls == 1`.
- **`sync.Mutex` + флаг.** Корректно, но многословнее и нужно вручную
  обеспечить, чтобы поздние вызовы не перевыполняли `init`. `Once` делает это в
  одну строку и оптимизирован (быстрый путь — атомарная проверка флага без
  захвата мьютекса).
- **`atomic.Bool` + lock.** То, что `Once` уже инкапсулирует. Изобретать заново
  — лишний риск ошибиться в видимости памяти.
- **`OnceFunc`/`OnceValue` (Go 1.21+).** Готовые обёртки: `sync.OnceValue(f)`
  возвращает функцию, мемоизирующую результат. Если бы `init` отдавала только
  значение, можно было бы использовать их; для пары «значение + error» —
  `OnceValues`. Эталон делает то же руками, что наглядно показывает механику.

## Сложность и поведение под нагрузкой

Быстрый путь `Once.Do` после первой инициализации — это атомарное чтение флага
(`atomic.Load`), без захвата мьютекса: O(1) и почти бесплатно. Только первый
вызов и конкуренты на старте проходят медленный путь под внутренним мьютексом.
Под высокой нагрузкой после прогрева `Do()` практически не имеет накладных
расходов — идеально для горячих ленивых синглтонов.

## Что спросит интервьюер дальше

- **«Почему ручной флаг — гонка?»** Чтение/запись `done` без синхронизации +
  возможный повторный запуск `init`.
- **«`Do` блокирует ждущих?»** Да — конкуренты ждут завершения первого `init`,
  поэтому все видят готовый результат.
- **«Где хранить `error`?»** В поле структуры, писать только внутри `f`,
  читать после `Do` — happens-before от `Once` обеспечивает видимость.
- **«Что если `init` паникует?»** `Once` считает попытку выполненной и больше не
  запустит `f`; паника всплывает. Для retry нужен другой механизм.
- **«Как сделать повторяемую инициализацию (например, с retry)?»**
  `golang.org/x/sync/singleflight` или новый `Once` на каждую попытку — `Once`
  одноразовый и не сбрасывается.

## В проде

`sync.Once` — стандартный способ ленивой инициализации: пулы, клиенты, парсинг
конфига, регистрация в `init`-подобных местах. В Go 1.21+ для этого есть
`sync.OnceFunc`, `sync.OnceValue`, `sync.OnceValues`. Для «один полёт на ключ»
(дедупликация одинаковых запросов) — `golang.org/x/sync/singleflight`. Подробнее
— [sync: примитивы](/book/sync-primitives).
