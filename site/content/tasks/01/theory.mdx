## Зачем это на собесе

`or` — это «объединитель отмены»: одна функция, которая срабатывает, как только
сработал **любой** из источников. Ровно так устроена отмена в больших системах:
запрос отменяют либо таймаут, либо родительский контекст, либо сигнал shutdown —
и нужно отреагировать на первое из событий. Интервьюер проверяет, понимаешь ли ты
закрытие канала как **broadcast** и умеешь ли строить композицию каналов без
утечки горутин.

## Что нужно знать

Главная идиома — **закрытый канал как широковещательный сигнал**. Чтение из
закрытого канала never blocks и сразу возвращает нулевое значение:

```go
done := make(chan struct{})
close(done)
<-done // не блокирует, мгновенно
<-done // и снова не блокирует — закрытие «видно» всем читателям
```

Поэтому закрытие одного канала может разбудить сколько угодно горутин,
ожидающих на `<-done`. Это фундамент пакета [context](/book/context) и
паттерна done-channel из главы [каналы](/book/channels) и [select](/book/select).

Второе — `select` ждёт сразу несколько каналов и просыпается на первом готовом:

```go
select {
case <-a:
case <-b:
}
```

## Идиомы и паттерны

- **Variadic + рекурсия.** Канонический `or` строится рекурсивно: делим вход на
  несколько «голов» и хвост, а хвост сворачиваем тем же `or`. Так одним `select`
  на 3–4 ветки можно слушать произвольное число каналов.
- **`defer close(out)`** в горутине гарантирует, что выходной канал закроется
  ровно один раз — как только `select` внутри разблокируется.
- **Передача собственного done внутрь рекурсии.** Чтобы вложенные горутины не
  повисли навсегда, в рекурсивный вызов добавляют сам `orDone` — тогда закрытие
  верхнего канала каскадом будит и завершает все нижние.

## Подводные камни

- **Утечка горутин.** Наивная реализация запускает по горутине на каждый канал,
  но после срабатывания первого не сигналит остальным — они виснут на `<-ch`
  навсегда. Каждая такая горутина — это удержанный стек и заблокированный
  отправитель. Проверь мысленно: «после возврата `or` все ли вспомогательные
  горутины умрут?»
- **Double close / запись в выход.** Закрывать `out` нужно один раз и только из
  одной горутины. `close` дважды — это паника.
- **Краевые случаи.** `or()` без аргументов и `or(c)` с одним каналом часто
  забывают. Что вернуть? (Подумай: «один источник — это и есть результат».)

## Как подступиться

1. Обработай вырожденные случаи: 0 каналов и 1 канал — без горутин вообще.
2. Заведи `orDone := make(chan interface{})` и горутину с `defer close(orDone)`.
3. Внутри горутины — `select`, слушающий несколько входов; на «много входов»
   сверни хвост рекурсивным `or`, **добавив туда `orDone`**, чтобы закрытие
   верхнего канала завершило вложенные горутины.
4. Проверь себя: запусти мысленно с 5 каналами, где один закрывается через 50 мс —
   выход должен закрыться почти сразу, а не ждать остальных.
